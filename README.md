# Ceiling certificates for synthetic-data performance figures — data and code

Deposit supporting the article *Can a synthetic-data performance figure be
checked without the real data? Ceiling certificates for evaluating and
commissioning health informatics tools*.

Everything here is released so that the verification protocol, the dependence
audit and the feature-group ablation can be repeated end to end.

---

## What is here

```
data/              the three synthetic datasets analysed in the article
generator/         the code that produced them
src/               the verification protocol, audit, ablation and figures
results/           every analysis artefact reported in the article
figures/           the two published figures, raster and vector
literature_audit/  the screening and extraction export behind eTable 2
requirements.txt   exact package versions used for the reported results
```

### data/

| File | Rows | Description |
| --- | --- | --- |
| `WHMD_realistic.csv` | 25 000 | Wearable health monitoring, 2000 users |
| `FTD_realistic.csv` | 20 000 | Emergency fleet telemetry, 148 vehicles |
| `PVETD_realistic.csv` | 10 000 | Automated crash notification, 9479 vehicles |

**The leakage channels reported in the article are present in these files as
generated and have not been removed.** That is deliberate: removing them would
make the audit impossible to reproduce.

### generator/

`ierda_realistic_generator.py` produced the three files above. It was run
**without** `--ierad_path`, so no record of the Integrated Emergency Response
Dataset entered the released data; the `linked_incident_id` column is empty in
all three files. The observation window and the three-level region taxonomy
were specified to align with that dataset, not read from it.

`ierda_data_generator.py` is an earlier pipeline that did read IERAD. **It did
not produce the released files** and is included only for completeness. The
`whmd_schema.py`, `ftd_schema.py`, `pvetd_schema.py` and
`ierda_integration_schema.py` files hold the field definitions and the
integration mapping.

The generator was not consulted during the analysis. It was examined afterwards
to check the inferences against it, and no reported figure was changed as a
result.

### Reproducing the analysis

```bash
pip install -r requirements.txt
python src/run_protocol.py      # certificates, ceilings, violation tests
python src/run_benchmark.py     # held-out and cross-validated performance
python src/run_ablation.py      # feature-group ablation
python src/make_figures.py      # figures 1 and 2
python src/verify_manuscript.py # re-derives every number in the article
```

`verify_manuscript.py` is the quickest check: it recomputes the certificates,
ceilings and derived quantities from the raw data and reports pass or fail
against the published values.

## Environment

The reported results were produced with the versions pinned in
`requirements.txt`. The figures reproduce to within 1e-3 under
scikit-learn 1.6.1 with later minor versions of XGBoost, pandas and NumPy, but
the pinned versions are the ones the published numbers come from.
